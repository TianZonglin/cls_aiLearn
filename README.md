# 博士实践课：用 AI 做一个工具

本仓库用于整理“博士实践课”的课程资料、实践流程和作业要求。课程目标是让每位同学在四周内借助 AI 完成一个可运行、可说明、可提交的小工具。

这里的“小工具”不要求是大型系统，但应尽量包含完整流程：输入、处理、输出，以及必要的保存、展示或说明。

## 课程目标

每位同学最终完成一个基于 AI 辅助开发的小工具。成果建议包含：

1. 工具说明文档。
2. 可运行的代码或配置文件。
3. 使用截图或演示材料。
4. 简短的实践总结。

可选方向包括：

- 学习辅助工具。
- 数据处理工具。
- 文档整理工具。
- 自动化脚本。
- 网页小应用。
- GitHub 项目说明生成工具。
- 其他能解决实际问题的小工具。

## 实践流程

推荐按照以下流程推进：

1. 构想工具：明确想解决什么问题，目标用户是谁。
2. 调研同类工具：了解已有产品或功能，避免目标过大。
3. 形成设计文档：将需求、功能、输入输出、边界情况写入 `design.md`。
4. 拆分实现步骤：将 `design.md` 拆成多个 `Step-X.md`，每一步都要有清晰输入、输出和校验。
5. 分步执行：让 Codex 按步骤逐个实现，每步完成后进行校验。
6. 调试微调：每轮修改控制在少量明确问题内。
7. 版本备份：达到阶段性成果后提交 Git，并推送到 GitHub。
8. 收尾提交：补充 README、使用说明、截图和总结。

## 课程安排

### 第 1 周：环境安装与工具准备

本周主要完成软件安装和基础配置。没有上过 AI 博士课，或之前没有配置好的同学，需要完整完成环境准备。

重点参考：

[study_0_softwares_installation.md](./study_0_softwares_installation.md)

### 第 2 周：安装问题处理与流程学习

如安装过程中遇到问题，可在正式上课前联系老师处理。

支持方式：

1. 线上沟通。
2. 到新创 1402 办公室处理。

课后重点阅读：

- [study_1_vibecoding_workflow.md](./study_1_vibecoding_workflow.md)
- [study_2_codex_cli_commands.md](./study_2_codex_cli_commands.md)

并开始设计自己的 `design.md`。

### 第 3 周：确定实践目标

交流各自的小工具设计，及时反馈和修改，最终确定能执行的设计细节。

课后一周内建议完成：

- 初步代码实现。
- 按 `Step-X.md` 分步骤执行。
- 修复明显错误。
- 及时提交并备份到 GitHub。

### 第 4 周：实践交流

交流每位同学完成的 AI 工具。课后一周内完成全部代码、文档和最终提交。

## GitHub 提交建议

建议在以下节点提交并推送：

- 完成 `design.md` 后。
- 完成 `Step-X.md` 拆分后。
- 完成一个可运行版本后。
- 完成调试和最终文档后。

常用命令：

```bash
git status
git add .
git commit -m "update course project"
git push
```

如果推送失败，先确认网络是否能访问 GitHub，再检查远程仓库地址：

```bash
git remote -v
```

## 选题建议

选题建议优先选择自己真实需要、范围清晰、四周内能够完成的工具。可以参考以下方向：

1. 课程资料自动整理工具。
2. 文献阅读辅助工具。
3. 表格数据分析助手。
4. 访谈或会议纪要生成工具。
5. 个人知识库问答工具。
6. 实验记录与报告生成工具。
7. 简历或项目材料优化工具。
8. 小型网页应用生成器。
9. GitHub 项目说明生成工具。
10. 作业批改辅助工具。

重点不是功能越多越好，而是流程完整、能运行、能解释、能交付。
